# xAgent v0.0.17.beta

发布日期：2026 年 9 月 9 日。
重发日期：2026 年 9 月 10 日。

本版本完善 AgentPlugin 工具卡展示与协议兼容，统一会话消息来源和协作语义，并增强模型流式调用恢复、上下文压缩、文件生命周期和失败诊断；同时发布六个官方 AgentPlugin，钉钉首次进入公开目录和四平台安装链路。

## 同版本重发修复（2026 年 9 月 10 日）

- 修复 Markdown 文档预览中的目录锚点被当作新网页打开的问题；点击目录链接现在会在当前预览内定位到对应标题。
- 会话输入框草稿会连同附件文件引用一起保存，切换会话后可以恢复附件；附件恢复完成前不会误发消息。
- 登录后的用户语言同步改为后台完成，不再临时卸载当前路由，避免登录成功后再次闪回登录页或要求重复登录。
- 模型、运行时和 API 失败会投影为稳定错误码并按当前界面语言显示；最近一次失败状态在会话重新进入后仍可见。
- 统一会话上下文用量口径，明确区分完整输入估算、Provider 实测输入、工具定义子集、输出预留、请求预算、压缩触发线和模型上下文窗口，避免把累计用量与当前请求混算。
- Context Compression 改为依据 AgentCore 的完整输入估算和模型输出预留触发；修复活跃请求压缩后当前真实用户输入未恢复而导致执行失败的问题。
- 将旧的 `OUTPUT_LIMIT` 拆分为普通输出截断、工具参数截断、输出参数无效和自动续写耗尽；服务端诊断保留脱敏后的上游错误、原始终止原因与用量。
- 预期的输出边界不再显示为会话运行标记或平台异常，Brain 包装层也不再重复记录所有者已经上报的错误；配置和 Provider 故障仍会保留。
- 本次重发仅更新 xAgent Server；官方 AgentPlugin 版本和制品保持不变。

## 安装

Linux 和 macOS 使用同一个安装命令：

```bash
curl -fsSL https://downloads.xagent.xiagaogao.com/scripts/install.sh | bash
```

安装器会自动识别操作系统和 CPU 架构，下载并校验对应发布包，安装或升级 xAgent Server，并可选择安装支持的 AgentPlugin。

## 主要更新

### AgentPlugin 工具卡

- AgentPlugin Card 可以为每个工具声明图标和安全摘要字段；xAgent 直接使用插件声明渲染工具卡，不再根据工具参数猜测展示内容。
- 展示 selector 只能读取当前工具公开 input/output schema 中已经声明的字段，并限制摘要数量、候选字段和分隔符长度。
- Browser Runtime 与微信、Telegram、飞书、Database、SSH、钉钉官方插件均补齐工具图标和关键参数摘要。

### 会话与协作

- 建立统一的 MessageContext 来源投影，覆盖 AgentPlugin、Trigger、跨会话消息和审批决定，时间线可以稳定展示真实消息来源。
- 删除独立的持久协作状态链，改由 `collaboration_request`、回复标记和 Session Prompt 驱动模型判断，避免状态与消息事实分叉。
- 修复空正文校验、公共通道来源伪造、AgentPlugin 精确回复和异步会话失败未反馈的问题。

### 上下文与文件生命周期

- Context Compression 会把单次摘要请求控制在摘要模型上下文窗口的 80% 以内；待压缩内容超出单批预算时，从最旧内容开始分批融合，全部成功后才提交原始消息边界和 checkpoint。
- 最终请求仍超过压缩触发线时，会继续收紧最近消息保留范围并执行后续压缩，避免持久化压缩完成后仍因上下文过大而中断。
- SSH 下载、微信图片及其他 AgentPlugin 拉取的文件统一进入当前 Session workspace，不再写入用户主动上传目录。
- Session 删除和过期清理现在容忍已经缺失的物理文件、孤立 AgentPlugin 通道及可确认失效的修复事实；单个会话清理失败也不会阻塞同批其他会话。

### 模型可靠性与诊断

- Provider 流式读取在首个有效事件前发生可重试中断时会自动重新建立请求；已经产生有效输出后不会重放，避免重复内容。
- 模型工具调用格式无效时继续执行既有自动修正；多次修正仍失败后，用户会收到明确的可行动提示。
- 区分内容策略拒绝、模型输入不合法、Provider 调用失败和模型工具调用格式无效；管理员事件记录稳定错误码、阶段、校验原因和脱敏后的 Provider 响应。

### AgentPlugin 兼容性

- Card revision 使用插件返回的原始 Card 快照计算，旧 schema 归一化不再造成 health revision 误判。
- 数据平面协商支持按插件 Card 声明回退到协议 `4.3` 或 `4.0`。
