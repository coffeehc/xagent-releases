# xAgent v0.0.16.beta

发布日期：2026 年 9 月 7 日。

本版本将原 Connector 能力整体升级为 AgentPlugin，在保持既有业务逻辑的基础上统一领域模型、协议命名、存储、管理界面、安装目录和发布链；同时新增 A2A Client，并补齐授权版本上限与相关容量治理。

## 安装

Linux 和 macOS 使用同一个安装命令：

```bash
curl -fsSL https://downloads.xagent.xiagaogao.com/scripts/install.sh | bash
```

安装器会自动识别操作系统和 CPU 架构，下载并校验对应发布包，安装或升级 xAgent Server，并可选择安装支持的 AgentPlugin。

## 主要更新

### AgentPlugin

- xAgent 内部不再保留 Connector 领域概念；原有接入逻辑直接更名并迁移到 AgentPlugin，不引入兼容映射或重新实现业务流程。
- 管理端使用 AgentPlugin Connector 管理插件服务，用户端只通过“插件连接”管理自己的 Channel。
- `ConnectionDescriptor` 更名为 `AgentPluginDescriptor`，描述协议使用 `xagent.agentplugin/v2`；IM 消息、Tool 调用、文件和管理 Profile 的业务语义保持不变。
- SQLite 与 PostgreSQL 启动迁移会把已有插件接入、用户 Channel、VChannel 和 Session purpose 转入 AgentPlugin 表与命名空间。
- 微信、Telegram、飞书、数据库和 SSH 官方插件使用新的程序名、服务名、配置根键、`agent-plugins/` 安装目录和 R2 `agentplugins/` 发布目录。

### 安装与升级

- 从 `0.0.16.beta` 开始，Linux `upgrade.sh` 只在目标版本达到迁移门槛且检测到已安装的旧 Connector 可执行文件时触发自动迁移。
- 自动迁移保留原组件完整配置和数据目录，安装并启动对应 AgentPlugin；确认新服务可用后才注销旧服务并清理旧程序与空目录。
- AgentPlugin 安装或启动失败时恢复旧目录、配置和服务；没有安装的旧组件不会被补装。
- 全新安装直接使用 AgentPlugin Catalog，不创建旧 Connector 目录或服务。

### A2A Client

- 新增用户级远端 Agent 管理和 Agent Card 发现，支持 A2A v1 JSON-RPC 与 HTTP+JSON，以及 API Key、Bearer 和已有 OAuth bearer token。
- 支持发送、查询、回复和取消远端任务；非终态任务优先使用 streaming，必要时回退轮询，并在服务重启后恢复监控。
- 远端 Message、Artifact、状态和错误进入不可变收件箱；有来源 Session 的可操作或终态结果会按稳定幂等身份回投原会话。
- 新增 A2A 连接、任务与结果统计，并按授权执行系统级 A2A 连接容量限制。

### 授权与运行管理

- 企业授权新增 `max_xagent_version`，安装授权、读取状态和自动升级时都会校验当前或目标 xAgent 版本。
- AgentPlugin Channel 容量字段统一为 AgentPlugin 命名，并新增 A2A 连接容量。
- 管理后台同步展示 AgentPlugin、A2A 权益和运行统计。

## 升级注意事项

- 升级前请备份 xAgent 配置、数据库、用户工作区、Memory、Skill、Tool 包及已安装插件的配置和数据目录。
- 已安装旧 Connector 的 Linux 机器应使用公开 `upgrade.sh` 或完整安装器升级，不要只手工替换 xAgent 二进制。
- 自动迁移只识别官方稳定二进制名。自定义服务或手工部署的旧组件需要按 AgentPlugin 的新程序名、配置根键和目录结构重新安装。
- 现有企业授权必须允许 `0.0.16.beta`；授权缺少最高版本或上限较低时，先重新签发授权再执行自动升级。
